Partie 1
Introduction
1.1 Objectifs et règles
L’objectif principal de ce miniprojet est d’écrire un parser (analyseur syntaxique)
d’images Mini-PNG, une version simplifiée du format d’images standard PNG1.
Les fonctionnalités attendues du programme consistent en trois fonctionnalités
principales de base et deux plus avancées :
1. Parser d’images noir et blanc Mini-PNG ;
2. Affichage et génération d’images ;
3. Gestion des images en niveaux de gris ;
4. Gestion des images en couleurs ;
5. Gestion de palette 256-couleurs.
Les objectifs du miniprojet sont les suivants :
• analyser et évaluer le standard Mini-PNG, ses faiblesses et ses risques ;
• concevoir puis implémenter un parser d’images Mini-PNG en noir et blanc, en
suivant le format décrit dans la partie 2 ;
• implémenter l’affichage des images lues ;
• concevoir puis implémenter un générateur d’ASCII Mini-PNG correct ;
• implémenter la gestion des images en niveaux de gris ;
◦ implémenter la gestion des images en couleurs ;
◦ implémenter la gestion de palette 256 couleurs ;
? assurer la portabilité2 du programme.
Les points indiqués par un disque noir “•” correspondent au minimum attendu.
Ceux indiqués par un cercle blanc “◦” correspondent à un bon niveau. Le point
identifié par une étoile noire “?” est plus complexe.

Description du format Mini-PNG
Une image au format Mini-PNG est constituée d’abord d’un marqueur de 8 octets
(parfois appelé magic number) suivi d’une liste de blocs. Le magic number de Mini-
PNG est simplement "Mini-PNG". La structure, les différents types de bloc et leurs
spécificités sont décrits dans les sections suivantes.
2.1 Structure générale d’un bloc
Les blocs composant le fichier sont de la forme suivante :
Offset Nom Taille Description
0 Type 1 octet Caractère décrivant le bloc
1 Taille λ 2 octets Valeur de λ, longueur en octets du contenu
3 Contenu λ octets Contenu du bloc (dépend du type)

Figure 2.1 : Structure des blocs.
Comme indiqué dans le tableau 2.1, le contenu dépend du type de bloc. Les types
classiques de bloc ainsi que la composition d’un Mini-PNG sont les suivants :
• un bloc d’en-tête H (header) ;
• zéro, un ou plusieurs blocs de commentaires C (comment) ;
• un ou plusieurs blocs de données D (data).
Les prochaines sections décrivent successivement chaque bloc.

2.2 Bloc en-tête H
Le bloc H décris les dimensions et la catégorie d’image. Les différentes catégories
d’image sont noir et blanc (NEB), niveaux de gris (NVG), palette 256 couleurs (P8C)
et couleurs 24-bits (C24). Chaque catégorie est associée à un chiffre, soit :
0 : NEB ; 1 : NVG ; 2 : C24 ; 3 : P8C.

2.4 Bloc de données D
Les blocs D contiennent les données des pixels de l’image. Leurs contenus doivent
être concaténés pour obtenir un bitmap de l’image.
Le codage des pixels dépend de la catégorie. Pour la catégorie “NEB” (pixels noirs
et blancs), chaque pixel doit être codé sur un bit (1 pour noir, 0 pour blanc). Les
autres types de pixels sont décris plus tard.

3.3.2 Q8 : Affichage et génération des niveaux de gris
Reprenez les questions de la section 3.2 en ajoutant le support de l’encodage en

Pour cela, notez qu’il existe des séquences d’échappement ANSI permettant d’af-
ficher les couleurs 24-bits dans un terminal. Elles commencent par le caractère AS-
CII 27 ("\033" en octal, "\x1b" en héxadécimal) suivi du crochet ouvrant "[", et
se termine par un "m". La syntaxe complète est riche et bien détaillée sur la page an-
glaise Wikipédia (voir https://en.wikipedia.org/wiki/ANSI_escape_code#).
Pour pouvoir les utiliser, le terminal doit les supporter. Pour vérifier le support,
vous pouvez utiliser le script shell ci-après.
Script de test niveau de gris
#! /bin/sh
for i in $(seq 0 255); do
RESET="\033[0m"
FG="\033[38;2;${i};${i};${i}m"
BG="\033[48;2;${i};${i};${i}m"
printf "%3d - FG: $FG$%3d$RESET - BG: $BG%3s$RESET\n" \
"$i" "$i" ""
done; echo

3.5 Prise en charge de palette 256 couleurs (difficile)
Contexte
Si l’affichage en true colors est pratique et facile à comprendre (description directe
de la couleur en RGB), il est en revanche très contraignant pour le matériel infor-
matique. En effet, il impose que la carte graphique (ou le processeur, en l’absence
de celle-ci) puisse distinguer et afficher 224 couleurs, soit environ 17 millions de
nuances différentes.
Si, de nos jours, le matériel graphique d’un PC peut très facilement gérer cette
charge, ce n’est pas forcément le cas de microcontrôleurs, et ce n’était pas le cas
dans les années 70-80.
Afin de palier au manque de mémoire, de puissance de calcul ou de bande pas-
sante, l’idée est venue d’utiliser une palette contenant au plus 256 couleurs diffé-
rentes.
Dans le cadre de Mini-PNG, il est nécessaire de définir comment sont implémenté
les blocs D dans le mode “P8C” et d’introduire un nouveau type de bloc, le bloc de
palette P.
Concernant les blocs D, les pixels y sont codés sur un octet. Cela représente l’in-
dice d’une couleur de la palette définie dans le bloc P, décris ci-après.
3.5.1 Bloc de palette P
Le bloc de palette P décris une palette contenant n couleurs (n un entier dans l’inter-
valle [1, 256]). Chaque couleur est associée à un entier croissant de 0 à n − 1. Le bloc P
doit être placé directement avant le premier bloc D lorsque le mode de l’image vaut
2 (“P8C”).
